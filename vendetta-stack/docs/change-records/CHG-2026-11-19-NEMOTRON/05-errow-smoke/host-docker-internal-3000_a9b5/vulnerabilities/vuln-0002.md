# Authentication Bypass via SQL Injection

**ID:** vuln-0002
**Severity:** CRITICAL
**Found:** 2026-11-19 10:37:34 UTC
**Target:** http://host.docker.internal:3000
**CWE:** CWE-89
**CVSS:** 9.1
**Confidence:** High
**Fix Effort:** Low

## Description

SQL injection in the login endpoint allows unauthenticated access to admin privileges.

## Evidence

HTTP/1.1 200 OK response with JSON containing an `authentication.token` field for admin user after injecting `' OR 1=1--` into the email field.

## Impact

Unauthenticated attacker can obtain a valid JWT granting admin access, leading to full account takeover.

## Counterevidence

If the backend sanitises input after the comment marker or uses a different query construction that neutralises the injection, the bypass would fail; also, if authentication required additional checks not present in the tested request, the bypass might be incomplete.

## What Would Change This Severity

If further testing reveals that the bypass only works under specific conditions (e.g., a particular SQL version or configuration) that are not present in production, the severity could decrease; if it works consistently across configurations, the severity remains high.

## Technical Analysis

The login endpoint interpolates the `email` field directly into the SQL query without proper parameterisation. Supplying `email":"' OR 1=1--"` closes the string, makes the condition always true, and comments out the password check, resulting in authentication bypass. The server issues a JWT for the admin user.

## Proof of Concept

1. POST to `/rest/user/login` with JSON body containing `"email":"' OR 1=1--","password":"x"`.
2. Server responds with a JWT token for the admin user.

```python
curl -sD - -X POST "http://host.docker.internal:3000/rest/user/login" -H 'Content-Type: application/json' -d '{"email":"'"'"' OR 1=1--","password":"x"}'
```

## Remediation

Implement proper parameterised queries or an allowlist for email inputs; validate credentials against stored hashes rather than constructing dynamic SQL.

## Assumptions

Login endpoint reachable without prior authentication; email field not sanitised before inclusion in SQL query.
