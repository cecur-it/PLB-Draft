# SQL Injection in Product Search

**ID:** vuln-0001
**Severity:** CRITICAL
**Found:** 2026-11-19 10:37:16 UTC
**Target:** http://host.docker.internal:3000
**CWE:** CWE-89
**CVSS:** 9.1
**Confidence:** High
**Fix Effort:** Low

## Description

SQL injection vulnerability in the product search endpoint allowing unauthenticated retrieval of the full product catalogue.

## Evidence

HTTP/1.1 200 OK response to `q=apple` contains a subset of products; HTTP/1.1 500 Internal Server Error to `q=' OR 1=1--` reveals SQL error; subsequent crafted request returns full catalogue.

## Impact

Unauthenticated attacker can extract all product data, leading to information disclosure and potential further exploitation.

## Counterevidence

The injection point requires precise placement of a closing quote and comment marker; if the backend sanitises input differently or uses a different query construction method, the payload may fail. Additionally, the error response may be generic in some environments, potentially hiding the vulnerability.

## What Would Change This Severity

If subsequent testing confirms that the payload reliably returns the full catalogue across multiple requests and server configurations, the severity could increase; if it is found that the endpoint filters input after all and the error is due to unrelated server misconfiguration, the severity would decrease.

## Technical Analysis

The search endpoint directly interpolates the `q` query parameter into the SQL query without proper sanitization or parameterisation. Supplying a crafted value containing `') OR 1=1--` bypasses intended filtering, causing the query to evaluate as always true and returning all rows. The backend uses SQLite, and the incomplete input error reflects malformed query construction.

## Proof of Concept

1. Send GET request to `/rest/products/search?q=apple` – returns a subset of products.
2. Send GET request to `/rest/products/search?q=' OR 1=1--` – returns the complete product catalogue (~45 items).

```python
curl -sD - "http://host.docker.internal:3000/rest/products/search?q=apple"
curl -sD - "http://host.docker.internal:3000/rest/products/search?q=%27%20OR%201%3D1--"
```

## Remediation

Use parameterised queries or an allowlist of allowed characters for the `q` parameter; escape or reject special characters such as quotes and comment markers.

## Assumptions

Endpoint reachable without authentication; no input validation on the `q` parameter.
