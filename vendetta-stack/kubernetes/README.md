# vendetta-stack on Kubernetes

Traces: PROMPT §1 Tier 3; CONTRACT §1 (pinned images), §2 (ports, names, secrets, PKI), §4.4 (gateway-only LLM access, FailClosed profiles), §8.

Two packagings of the same manifests, both validated with `helm lint`, `helm template`, `kustomize build` and `kubeconform -strict`:

| Path | What it is |
|---|---|
| `helm/vendetta-stack/` | the chart (source of truth); `values.yaml` = production-shaped defaults, `values-onprem.yaml`, `values-airgap.yaml` = overlays |
| `helm/vendetta-stack/sync-files.sh` | keeps `files/` (ConfigMap sources copied from `fluent-bit/`, `opensearch/`, `prometheus/`, `grafana/`, `ollama/`, `errow/`) identical to the stack; `--check` (default) / `--write` |
| `kustomize/base/` | `helm template` output of the chart defaults (`resources.yaml`, generated by `kustomize/render-base.sh --write`) + the Namespace |
| `kustomize/overlays/{dev,onprem,airgap}` | patches on the base: single-node dev, StorageClasses/GPU pool/Ingress/registry, internal registry + offline bundles |

Service names equal the Compose service names (`opensearch`, `fluent-bit`, `llm-gateway`, …) because the shipped configs address them literally: **one release per namespace**.

## Prerequisites

* Kubernetes 1.27+, a default block StorageClass, and a **ReadWriteMany** StorageClass for the volumes shared by the Errow pods (`errow-runs`, `errow-ndjson`, `errow-shipper-state`, `feedback-loop`, `opensearch-snapshots`). Without RWX set `global.sharedAccessMode=ReadWriteOnce`: the chart then pins the pods that share a volume to one node (pod affinity to `errow`).
* Nodes: `vm.max_map_count=262144` (the OpenSearch pod runs a privileged `sysctl` init container; set `opensearch.setMaxMapCount=false` when the node image already sets it or the namespace forbids privileged pods).
* GPU pool for Ollama: NVIDIA device plugin or GPU Operator advertising `nvidia.com/gpu`, nodes labelled `vendetta-stack/gpu=true` and tainted `nvidia.com/gpu=:NoSchedule`:

  ```bash
  kubectl label node <gpu-node> vendetta-stack/gpu=true
  kubectl taint node <gpu-node> nvidia.com/gpu=:NoSchedule
  ```
* The namespace must allow privileged pods (`errow-dind` is privileged; the Vendetta manager, when enabled, runs as root). `kustomize/base/namespace.yaml` sets Pod Security `enforce: privileged`; every other pod carries a restricted-grade `securityContext` (non-root, read-only root filesystem where the image allows, `drop: [ALL]`, `RuntimeDefault` seccomp).
* Optional: cert-manager (`certManager.enabled`), prometheus-operator CRDs (`monitoring.serviceMonitor.enabled`), external-secrets (`externalSecrets.enabled`), an NGINX ingress controller (`errow.viewer.ingress.enabled`).

## 1. Build and publish the local images

`vendetta-stack/{fluentd,llm-gateway,ollama,errow,errow-mcp,errow-shipper,errow-feedback,errow-sandbox}` are built from the repository (`docker compose build`, tag `1.0.0` = `STACK_VERSION`), then pushed to your registry; set `global.imageRegistry` (Helm) or the `images:` block of the overlay (kustomize) to that registry. Third-party images are pinned by digest in `values.yaml` and mirror the compose `.env.example` pins.

## 2. Secrets and PKI (never in values files)

`scripts/bootstrap.sh --extra-services errow-dind,errow-dind-client` creates `secrets/` and `pki/` (the two extra certificates are the Docker TLS server and client identities of `errow-dind`). Then, in the target namespace:

```bash
kubectl create namespace vendetta-stack
kubectl -n vendetta-stack create secret generic vendetta-stack-secrets \
  --from-file=opensearch_admin_password=secrets/opensearch_admin_password \
  --from-file=llm_gateway_token=secrets/llm_gateway_token \
  --from-file=errow_api_token=secrets/errow_api_token \
  --from-file=grafana_admin_password=secrets/grafana_admin_password \
  --from-file=feedback_webhook_token=secrets/feedback_webhook_token \
  --from-file=vendetta_api_password=secrets/vendetta_api_password \
  --from-file=cs3_approval_token=secrets/cs3_approval_token

pki_args=()
for f in pki/*.crt pki/*.key; do [[ $f == pki/ca.key ]] || pki_args+=(--from-file="$f"); done
kubectl -n vendetta-stack create secret generic vendetta-pki "${pki_args[@]}"
```

The CA private key (`pki/ca.key`) never enters the cluster. With `certManager.enabled=true` the `vendetta-pki` Secret is not used: a self-signed bootstrap Issuer creates the CA Certificate `vendetta-ca-root`, a CA Issuer signs one Certificate per service (ECDSA P-384, SANs: service name, `<svc>.<ns>`, `<svc>.<ns>.svc`, `localhost`, `127.0.0.1`) and the pods mount `tls.crt` / `tls.key` / `ca.crt` of `<service>-tls`. With `externalSecrets.enabled=true` the chart renders `ExternalSecret` resources (store `externalSecrets.secretStoreRef`, keys under `externalSecrets.remoteKeyPrefix`) that produce the same Secret names.

Optional Secrets (only when the matching feature is on; the key names of the legs Secret are `fluentBit.legs.*.ingestKeyKey` / `tokenKey` in `values.yaml`):

```bash
kubectl -n vendetta-stack create secret generic vendetta-cs3-legs \
  --from-file=console_ingest_key=<ingest key file> --from-file=siem_token=<SIEM token file>
# keys/<approver>.key is required for dual control (config.approvalThreshold, default 2 distinct approvers);
# feedback_approval_key alone clamps the threshold to 1
kubectl -n vendetta-stack create secret generic vendetta-feedback-approval \
  --from-file=feedback_approval_key=secrets/approval/feedback_approval_key \
  --from-file=keys/alice.key=secrets/approval/keys/alice.key \
  --from-file=keys/bob.key=secrets/approval/keys/bob.key
kubectl -n vendetta-stack create secret generic errow-viewer-basic-auth --from-file=auth=./htpasswd
kubectl -n vendetta-stack create secret tls vendetta-stack-tls --cert=viewer.crt --key=viewer.key
```

## 3. Install

```bash
# Helm (cluster with a block + RWX StorageClass, cert-manager, a GPU pool)
helm upgrade --install vendetta-stack kubernetes/helm/vendetta-stack -n vendetta-stack \
  -f kubernetes/helm/vendetta-stack/values-onprem.yaml
kubectl -n vendetta-stack wait --for=condition=complete job/opensearch-init --timeout=15m

# Kustomize
kustomize build kubernetes/kustomize/overlays/onprem | kubectl apply -f -

# Single-node dev cluster (kind, k3d, minikube): one OpenSearch node, Ollama on CPU, RWO volumes
kustomize build kubernetes/kustomize/overlays/dev | kubectl apply -f -
```

Edit the StorageClass names (`ceph-block`, `cephfs`), the registry host and the Ingress host in the onprem files first. Other useful values: `opensearch.replicas` (1 selects `opensearch.single-node.yml` and a single-node init), `ollama.mode=gpu|cpu|mock|none` (`mock` runs the deterministic mock worker used by the smoke test), `fluentBit.variant=distroless|debug`, `fluentd.hpa.enabled`, `llmGateway.hpa.enabled`, `manager.enabled` (Vendetta manager; agents reach 1514/1515 through `manager.agentService.type`), `errow.feedback.poller.enabled` (CronJob running `vendetta-to-errow.sh --via-llm`), `errow.scanTarget.enabled` (the lab nginx), `fluentBit.hostLogs.enabled` (journald and host log files on every node).

### NetworkPolicies

Default-deny for every pod plus explicit allows. The invariants of CONTRACT §4.4 hold in the render: only the `llm-gateway` pod can open `ollama:11443`; Ollama has no egress (except `ollama.pullEgress` outside the airgap profile); `errow` and the sandbox cannot reach the Vendetta ports 1514/1515/1516/55000, Ollama 11434 or OpenSearch 9200; OpenSearch is reachable only from fluentd, `opensearch-init`, the dashboards, Grafana, Prometheus and `errow-feedback`. External egress (cloud legs, SIEM, model registry) is opened only through `networkPolicy.externalEgress`, `ollama.pullEgress`, `errow.dind.pullEgress` (`- {cidr: 203.0.113.0/24, ports: [{port: 443}]}`) and is ignored in the airgap profile. Scan targets outside the cluster need their CIDR under `errow.dind.targetEgress`. NetworkPolicy needs a CNI that enforces it (Calico, Cilium); `networkPolicy.dnsNamespace`, `dnsPodLabels` and `ingressControllerNamespace` adapt the DNS and Ingress allows.

### Reaching the UIs

Grafana, Prometheus and Alertmanager have no Ingress: `kubectl -n vendetta-stack port-forward svc/grafana 3000:3000`. The Errow viewer has no authentication of its own: expose it only through `errow.viewer.ingress` (basic-auth Secret + TLS Secret) or `port-forward svc/errow-viewer 8765:8765`.

### Scan target name

Sandbox containers run inside `errow-dind` and use the cluster DNS. To make `scan-target.vendetta.lab` resolve to the lab target (`errow.scanTarget.enabled`), add to the CoreDNS Corefile: `rewrite name scan-target.vendetta.lab scan-target.vendetta-stack.svc.cluster.local`.

## 4. GPU node pool

Ollama runs as a StatefulSet (`ollama`, headless Service `ollama-workers`, mTLS worker proxy on 11443, model store PVC 200 Gi). It requests `nvidia.com/gpu: 1` (`ollama.gpu.*`), selects `vendetta-stack/gpu: "true"` and tolerates `nvidia.com/gpu`. For a runtime class (`ollama.gpu.runtimeClassName: nvidia`) or another GPU resource name (MIG slices) set the matching values. Scale workers with `ollama.replicas`; the gateway balances over `ollama-workers`. The gateway pod (2 replicas, spool PVC per replica, HAProxy `ollama-lb` sidecar sharing its network namespace) is the only client.

## 5. Air-gapped install

Build the bundle on a connected host with `scripts/build-airgap-bundle.sh`, verify it in the enclave with `scripts/verify-bundle.sh`, then:

1. Load every `images/<name>.tar` into the internal registry (`docker load` + `docker tag` + `docker push`, or `skopeo copy docker-archive:… docker://registry.airgap.local:5000/…`) keeping the repository paths (`registry.airgap.local:5000/vendetta-stack/errow:1.0.0`, `…/opensearchproject/opensearch:2.17.1`, …). The sandbox image `vendetta-stack/errow-sandbox:1.0.0` is pushed too.
2. Create two PVCs and fill them from the bundle (a one-off pod mounting the claim and `kubectl cp`): `ollama-model-bundle` with the bundle's `models/` directory (Ollama store layout, blobs verified against `ollama/models.json`) and `errow-bundle` with `errow-sandbox.tar` (`docker save vendetta-stack/errow-sandbox:1.0.0`).
3. Install with the overlay: `helm upgrade --install vendetta-stack kubernetes/helm/vendetta-stack -n vendetta-stack -f kubernetes/helm/vendetta-stack/values-airgap.yaml` or `kustomize build kubernetes/kustomize/overlays/airgap | kubectl apply -f -`. Edit `registry.airgap.local:5000` to your registry (`global.imageRegistry` / the `images:` block).

The airgap profile sets `CS3_PROFILE=airgap` for every pod (the gateway exits with code 3, `FailClosedError`, if a cloud LLM key is configured), `imagePullPolicy: IfNotPresent`, creates no egress rule beyond the cluster, refuses external legs and Errow Cloud at render time, and never pulls models.

## 6. Upgrade

```bash
kubernetes/helm/vendetta-stack/sync-files.sh --check          # chart files/ still mirror the stack configs (--write to refresh)
kubernetes/kustomize/render-base.sh --check                   # kustomize base still equals the chart render (--write to refresh)
kubectl -n vendetta-stack delete job opensearch-init --ignore-not-found   # kustomize only; Helm recreates it as a post-upgrade hook
helm upgrade vendetta-stack kubernetes/helm/vendetta-stack -n vendetta-stack -f <your values>
```

Pods roll when a ConfigMap they mount changes (checksum annotations). Rotate certificates with `scripts/rotate-certs.sh --kubernetes` (cert-manager renewal + ordered `rollout restart` of every workload labelled `app.kubernetes.io/part-of=vendetta-stack`), or re-create `vendetta-pki` and restart the workloads. Check health with `scripts/healthcheck.sh --kubernetes --namespace vendetta-stack`.

## Operational notes

* **Scaling fluentd in**: each fluentd replica owns a file buffer PVC. Lowering `minReplicas` or deleting a pod leaves its PVC; drain the buffer (it is flushed by the restarted pod) before deleting the claim.
* **Fluent Bit** runs as a DaemonSet (node logs, journald with `fluentBit.hostLogs.enabled`) and as the single-replica `fluent-bit-shared` Deployment for the shared logs (`errow-ndjson`, `vendetta-logs`). The default image is distroless (httpGet probes); it cannot rotate its safety files, use `fluentBit.variant=debug` for that.
* **HAProxy sidecars** (`ollama-lb`, worker proxy) bind their stats/health ports on loopback, so their probes run `wget` inside the container instead of httpGet.
* **Vendetta manager** (`manager.enabled`): runs as root with the capability list in `manager.capabilities`; merge `vendetta/ossec-hooks.conf` into its `ossec.conf` before enabling the fluentd execd hook.
* **Dashboards** (`opensearch.dashboards.enabled`): the image is large; run `/opensearch/dashboards/import.sh` from the `opensearch` pod to load the saved objects.
* The NGINX balancer variant exists only in Compose (`--profile nginx-lb`); Kubernetes always uses the HAProxy sidecar.

## Compose quick reference

`docker-compose.yml` (profiles `dashboards`, `mock-llm`, `llm`, `nginx-lb`, `errow`, `lab`, `manager`, `poller`, `test`) is configured by `.env` (from `scripts/bootstrap.sh`) or by `.env.smoke`. Keys and secrets are read by non-root containers: run `scripts/bootstrap.sh --key-group 10001` (matching `STACK_KEY_GID`) or, for local development only, `--dev-readable-keys --dev-readable-secrets`. Create `secrets/approval/` for the feedback approval key and `secrets/cs3-legs/` for the outbound legs when those features are enabled. The header of `docker-compose.yml` lists the bring-up commands; restart `ollama-lb` after restarting `llm-gateway` (they share a network namespace). `docker-compose.gpu.yml` adds NVIDIA passthrough and the `gpu-util` sidecar for `ollama_gpu_memory_util`; without the NVIDIA runtime use `--profile mock-llm` or run Ollama on CPU.
